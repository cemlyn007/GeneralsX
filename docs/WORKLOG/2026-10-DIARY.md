## 02/10/2026
### PLAN-023 Phase 0 fix round (PR #18 review)
- **Context**: review of PR #18 (PLAN-023 Phase 0 prerequisites) found several behavioural gaps and stale plan/audit text on top of the 28/09 change. The behavioural fixes below landed without a worklog entry at the time; this entry covers them together with the fixes from the fix round that followed.
- **Changes**:
  - **Embedded-mode crash UI**: `ReleaseCrash`/`ReleaseCrashLocalized` no longer call `ShowWindow(SW_HIDE)`, `TriggerMiniDump()` (which shuts down the process-wide `MiniDumper`) or print the Linux "FATAL ERROR" stderr banner when `IsEngineEmbeddedMode()` is set, since a host embedding more than one engine keeps the window and the other engines running after the throw. The two throw sites per function are deduplicated through one `ThrowIfEmbedded` helper.
  - **Sticky fault latch**: new exported `HasEngineFaulted()`/`ClearEngineFault()` (`Common/FatalEngineError.h`), set by `ThrowIfEmbedded` right before every embedded-mode throw. A `catch (...)` between `RELEASE_CRASH` and a host entry point that swallows the exception instead of rethrowing it still leaves this latch set, so a polling host can detect the fault anyway. Clearing it is the host's job, at every point it handles a fault (caught or polled); rlgenerals' `launcher::mark_faulted` now does this unconditionally, since a host that only cleared it on the polling path left it set across the next, unrelated call after a *caught* fault.
  - **Per-instance scratch-pad maps** (`GameStateMap.cpp`/`.h`, both games): `clearScratchPadMaps` deletes only the paths this instance's own `extractAndSaveMap` wrote (`m_scratchPadMaps`), not every `*.map` in the shared, process-wide Save directory — the old whole-directory sweep could delete a scratch-pad map a different live engine still needed. The path is now recorded *before* `extractAndSaveMap` runs (deduplicated), so a partial file from a truncated or corrupt load is tracked and cleaned up too, not only a successful extraction. This does not make two engines safe to load or save the *same map leaf* concurrently: the scratch path is named after the map leaf alone, so they still collide on the identical file (documented on `m_scratchPadMaps`, PLAN-023's Phase 0 status table).
  - **`iterateSaveFiles`** (`GameState.cpp`, both games): on non-Windows, lists the save directory directly with `std::filesystem::directory_iterator` (case-sensitive, regular files only) instead of `TheLocalFileSystem->getFileListInDirectory`, which case-folded two differently-cased save files together and could hand a FIFO, socket or dangling symlink to the load path. A non-ENOENT directory error (permissions, a mid-read I/O failure) is now reported on stderr the same way `StdLocalFileSystem` does, so a silently short listing is not silent.
  - **Null-mode `NEW`/`MSGNEW`/`newInstance`/`newInstanceDesc`**: pass constant tag arguments to the exported `(size_t, const char *, int)` overload instead of `__FILE__, __LINE__`, which grew `libgeneralsx.so`'s `.rodata` with an absolute compile-time path per call site and leaked the sandbox's build path into otherwise-identical builds. The overload already discarded both arguments in Null mode.
  - **MiniAudio Bink PCM**: `MiniAudioStream::bufferData` no longer appends decoded Bink video PCM to `m_buffer` when the stream has no engine (`MiniAudioManagerDummy::getHandleForBink`'s streams never call `setEngine`), which grew unboundedly on a long video with nothing ever draining it.
  - **`SAGE_USE_FFMPEG` + OpenAL dummy**: a `#error` now fails the build if `SAGE_USE_FFMPEG` is on with the OpenAL dummy backend, since `OpenALAudioManagerDummy::getFileLengthMS`'s hardcoded 0 only matches the real backend while that option is off.
  - **`scripts/qa/test-gamememorynull-exports-linux.sh`**: fixed a SIGPIPE/pipefail bug (`printf ... | grep -qx`, which closes its producer's stdin as soon as it matches, killing `printf` with SIGPIPE under `set -o pipefail`) that made every "must be exported" check fail on any real binary regardless of whether the engine was correct. Wired into `bazel test` (rlgenerals' `//rlgenerals/generalsx:gamememorynull_exports_test`).
  - **Comment and plan-doc accuracy**: fixed a wrong pooled-build analogy and a stale macro-expansion claim in the zero-fill audit (`GameMemoryNull.h`, `ZERO_FILL_MEMBER_INIT_AUDIT_2026-09-27.md`); synced PLAN-023's consumer Answer 1 (thread migration) with the wording already revised in the base plan PR; corrected PLAN-023's claim that the MiniAudio dummy was never built (the `linux64-miniaudio` CMake preset compiled it, in Docker, on Linux; it has still never been *run*); fixed PLAN-023's stale credit and status for the scratch-pad/`iterateSaveFiles` row, and its header's "Phase 0 done" against the same document's own pending acceptance criterion; recorded the Windows `extern "C"`/`/EHsc` exception-propagation gap in PLAN-023, where PR #18's description already claimed it was documented.
  - Backported to Generals where the files are duplicated.
